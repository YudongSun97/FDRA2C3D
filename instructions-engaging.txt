Note: the script makescript.sh contains many of these steps in a convenient form (but doesn't set paths for you).

(1) load required modules. On the engaging cluster, I can't compile FDRA with the newest MPI version (3.1.3) and I'm working with tech support to fix that. In the meanwhile, we use MPI 1.8.8. Since compiling can be finicky, I suggest purging loaded modules and loading only what you need:

module purge 
module load engaging/openmpi/1.8.8 

(2) set paths to required libraries in the Makefile.
fdra2c has the following dependencies:

- BLAS
- HMMVP (requires BLAS, LAPACK)
- UTIL (requires BLAS, LAPACK)
- DC3DM

BLAS: in theory, it can be loaded as a module:  (module load blas/gcc/64/1) and then set the following path in the makefile: 
BLASLIB = /cm/shared/apps/blas/open64/1/lib64/libblas.a
However, when I do this I get an error upon compiling. Therefore I downloaded BLAS and I use a local installation instead. Similarly, I use a local installation of lapack.

HMMVP/UTIL: see point 3 below.
DC3DM: can be downloaded from https://github.com/ambrad/dc3dm.

(3) Compile required libraries: HMMVP and UTIL. For convenience, these can be found in the folder: work/fdra2c/external. Each have two options for compiling: serial and parallel (same options as FDRA). Compile them as follows:
	(3.1) cd external/util/
	(3.2) set paths to BLAS and LAPACK into Makefile
	(3.3) made mode=s OR make mode=p (to compile serial or parallel versions)
	(3.4) repeat same steps for HMMVP.

(4) Back into the fdra2c folder, make sure the HMMVP and UTIL paths are set correctly in the Makefile; clean the folder (this needs to be done especially between serial/parallel compilation) and compile:

make clean
make mode=s OR make mode=p

(5) compile a subsidiary program that adds boundary conditions to a simulation:

make mode=p add_bc

(6) To set up and run simulations from matlab, you will need functions from these other folders/repositories:

	fdra2c-bp7/work/fdra2c/matlab/
	https://github.mit.edu/faultmech-mit/matlab-misc (contains auxiliary functions, may or may not be needed)
	https://github.mit.edu/faultmech-mit/matlab-fdra2c (contains postprocessing functions)
	https://github.mit.edu/faultmech-mit/seas (contains functions to upload SEAS results)

(7) Here is an example workflow:

  (7.1) Start with the matlab script: fdra2c-bp7/work/fdra2c/matlab/bp7.m to create FDRA input. You will need to modify the script by setting up paths to your DC3DM and FDRA2C installations, and a path for the FDRA simulation files. Look at the script to get an idea of how the model is set up. Then call the script (the argument "1" will ensure that DC3DM is run, which calculates Green's functions and compress the matrix):

	s = bp7('setup',1);

  (7.2) cd to the FDRA simulation folder. The file "script.sh" contains the commands to add boundary conditions and run the FDRA simulation. You can run the script (prepend "mpirun" if you want to run it in parallel), or copy into a slurm script.

  (7.3) when the simulation is done (or even before it's finished), you can load the files in matlab using the script: matlab-fdra2c/q2load.m. The repo contains other functions that can be used to make plots.

  (7.4) to convert simulations to the format required by SEAS, modify the script: seas_print_bp5.m in the "seas" repository to match BP7. 


(8) SEAS benchmark BP7. We can run FDRA simulations in 2 ways: with 1D slip (fixing rake direction) or 2D slip (allowing slip horizontally and vertically). The latter takes much more computing time and memory, and in some cases like a planar strike-slip faults it addes little value. I would like to test both approaches. This can be set in the bp7.m script, by setting the variable: ncomp=1, ncomp=2 respectively. We can then submit both to SEAS.

!! Important. I have not tested 2D slip with MPI, and it may be broken. Since this is a small problem, you will probably be ok running everything with the serial version; or you may want to use the parallel version 1-D slip but not 2-D.
